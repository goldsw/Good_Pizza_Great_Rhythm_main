# 작업 계약

**읽는 사람:** 에이전트 A·B·C 전원. 작업 시작 전에 이 문서를 먼저 읽는다.
**기준 문서:** `Docs/좋은_피자_위대한_리듬_기획서.md`, `Docs/Unity_구조.md`
**프로젝트:** Unity 6000.6.1f1, URP 2D, Input System 1.20.0

이 문서는 세 에이전트가 동시에 작업해도 충돌하지 않게 하는 경계다. 아래 타입 시그니처는 **그대로** 쓴다. 바꾸고 싶으면 코드를 고치지 말고 사람에게 묻는다.

---

## 1. 폴더와 어셈블리

에이전트는 자기 폴더 밖의 파일을 만들거나 고치지 않는다.

| 폴더 | 어셈블리 | 네임스페이스 | 참조 | 주인 |
| --- | --- | --- | --- | --- |
| `Assets/GPGR/Charting/` | `GPGR.Charting` | `GPGR.Charting` | 없음 | A |
| `Assets/GPGR/Runtime/` | `GPGR.Runtime` | `GPGR.Runtime` | `GPGR.Charting` | B |
| `Assets/GPGR/View/` | `GPGR.View` | `GPGR.View` | `GPGR.Charting`, `GPGR.Runtime` | C |
| `Assets/GPGR/EditorTools/` | `GPGR.EditorTools` (Editor 전용) | `GPGR.EditorTools` | `GPGR.Charting`, `GPGR.Runtime` | A |
| `Assets/GPGR/Charts/` | — (에셋) | — | — | A |
| `Assets/GPGR/Scenes/`, `Assets/GPGR/Art/`, `Assets/GPGR/Prefabs/` | — | — | — | C |
| `AgentScripts/` (Assets 밖) | — | — | — | 공용, 파일명으로 나눈다 |

네임스페이스가 `GPGR.Chart`가 아니라 `GPGR.Charting`인 이유: `Chart`라는 이름을 프로퍼티로도 쓰기 때문에(`TimelineDirector.Chart`) 타입 조회가 모호해지는 것을 피한다.

### 씬과 프리팹

`.unity`와 `.prefab`은 **C만** 만들고 고친다. A와 B는 씬에 손대지 않는다. 텍스트 병합이 사실상 불가능해서 그렇다. A·B가 씬에 뭔가 올려야 하면 C에게 요청 사항으로 남긴다.

`.meta`는 각자 만든 파일의 것만 생긴다. 남의 `.meta`를 지우지 않는다.

### 기존 파일

`Assets/Welcome/`, `Assets/Scenes/SampleScene.unity`, `Assets/Settings/`는 건드리지 않는다. `InputSystem_Actions.inputactions`도 고치지 않는다. B는 입력을 코드에서 직접 읽는다.

## 2. 공통 규칙

- **재료 이름으로 분기하지 않는다.** 디렉터·원판·연출은 "치즈"라서 다르게 도는 게 아니라, 행에 적힌 경로 키와 히트 목록이 달라서 다르게 돈다. `if (name == "치즈")` 같은 코드는 리뷰에서 되돌린다.
- **각도 규약:** 오른쪽 0°, 반시계가 양수. 왼쪽 180°, 하단 270°. `Mathf.DeltaAngle`처럼 짧은 쪽으로 꺾는 함수를 쓰지 않는다. 키에 적힌 부호 있는 각도를 그대로 쓴다.
- **시간 단위:** 데이터는 전부 **박(beat)**. 밀리초는 판정 창에서만 쓴다. 변환은 `SongChart.BeatsFromMs` / `MsFromBeats`만 쓴다.
- **숫자를 코드에 박지 않는다.** 모든 연출·판정 수치는 `SongChart` 또는 컴포넌트 인스펙터에 노출한다. 아래 7절의 잠정값은 기본값으로만 쓴다.
- **기획 문서를 고치지 않는다.** `Docs/*.md` 중 이 계약 문서 말고는 읽기만 한다. 모순을 찾으면 고치지 말고 사람에게 보고한다.
- 로그는 `Debug.Log` 대신 각 어셈블리의 `GpgrLog` 같은 래퍼를 쓰지 않아도 되지만, 프레임마다 찍는 로그는 남기지 않는다.

## 3. Unity CLI를 쓴다

**`unity` CLI가 PATH에 있고(1.0.0-beta.8), 이 프로젝트에 `com.unity.pipeline`이 설치되어 있고, Editor가 켜져 있다.** 코드를 짜고 "컴파일되는지 모르겠다"로 끝내지 말고 CLI로 확인한다.

시작할 때 한 번:

```bash
unity command editor_status                      # status: "ready" 를 확인
unity command set_autotick --enable true         # 창이 비활성일 때도 Editor가 돌게 한다. 필수
```

`unity command`를 이름 없이 부르면 쓸 수 있는 명령 전체가 나온다.

### Editor는 하나뿐이고 셋이 공유한다

이게 가장 조심할 점이다. 명령은 한 번에 하나만 실행되고, `recompile`은 도메인 리로드를 일으켜 남이 하던 일을 끊는다.

| 명령 | 누가 |
| --- | --- |
| `editor_status`, `find_gameobjects`, `get_*`, `list_*`, `console`, `screenshot` | 누구나. 읽기라서 안전하다 |
| `recompile`, `recompile_status`, `run_tests` | 누구나. 남이 돌리는 중이면 큐에 쌓여 느려질 뿐이니 조용히 기다린다 |
| `editor_play`, `editor_stop`, `editor_pause` | **C만.** 플레이 모드는 하나뿐이다 |
| `create_scene`, `open_scene`, `save_scene`, `create_prefab`, `create_gameobject`, `add_component`, `set_component_properties`, `set_transform` | **C만.** 파일 소유권과 같은 규칙이다 |
| `create_asset`, `write_text_file`, `menu`, `import_asset` | 자기 폴더 대상일 때만 |
| `build`, `switch_build_target`, `set_build_settings`, `package_add`, `package_remove`, `quit` | 아무도. 필요하면 사람에게 묻는다 |

`editor_status`가 `blocked_by_dialog`를 돌려주면 Editor에 모달 창이 떠 있다는 뜻이다. **재시도하지 말고** 어떤 창인지(`dialog.title`) 사람에게 알린다. CLI로는 못 닫는다.

### 컴파일 확인 루프

```bash
unity command recompile
unity command recompile_status     # "completed" 또는 "up_to_date" 까지 반복
```

도메인 리로드가 도는 동안 연결 오류가 나는 건 정상이다. `failed: true`면 `errors` 배열을 읽고 고친 뒤 다시 돈다.

### 테스트

```bash
unity command list_tests --mode editor
unity command run_tests --mode editor --filter GPGR.Charting.Tests
```

테스트가 **실패하면** 결과가 뭉개져 나올 수 있다. 그때는 `--filter`를 한 테스트로 좁혀 다시 돌린다.

`run_tests --mode playmode`는 플레이 모드를 잡는다. C가 플레이 중이면 실패하니, 되도록 EditMode 테스트로 짠다.

### 씬과 프리팹은 빌더 스크립트로 만든다

에이전트는 Editor를 클릭할 수 없다. 씬을 손으로 조립할 방법이 없으므로 **코드로 만든다.**

권장하는 방식은 빌더 패턴이다. `AgentScripts/`(**`Assets/` 밖**)에 C# 파일을 두고 정적 진입점을 부른다.

```bash
unity command run_script --file AgentScripts/C_BuildTrailerScene.cs --entry TrailerSceneBuilder.Build
unity command run_script --file AgentScripts/C_BuildTrailerScene.cs --dry_run true   # 컴파일만 확인
```

`Assets/` 밖이라 에셋 임포트도 도메인 리로드도 일어나지 않고, 한 번 도는 데 2초쯤이다. 씬 파일이 깨져도 빌더를 다시 돌리면 복구된다. **씬이 재현 가능해진다는 게 더 큰 이점이다.**

`create_scene` + `create_gameobject` + `add_component` + `set_component_properties` + `save_scene`을 하나씩 부르는 방법도 있지만, 오브젝트가 열 개를 넘으면 빌더가 훨씬 빠르다.

`AgentScripts/`는 셋이 같이 쓰므로 파일명에 소유자를 붙인다. A는 `A_*.cs`, B는 `B_*.cs`, C는 `C_*.cs`.

### 화면을 눈으로 확인한다

```bash
unity command screenshot --view game --output Temp/shot.png
unity command capture_game_view --save_path Screenshots/shot.png --source screen   # Play Mode. 오버레이 UI까지 들어온다
unity command capture_scene_view --save_path Screenshots/scene.png
```

에이전트가 자기 작업 결과를 볼 수 있는 유일한 수단이다. "됐을 것이다"로 끝내지 말고 찍어서 본다.

### 메뉴 실행

```bash
unity command menu --path "GPGR/Create Demo Chart Asset"
unity command menu                                  # 쓸 수 있는 메뉴 목록
```

### 종료 코드

`2`는 인자가 틀렸다는 뜻이다. 명령줄을 고쳐 다시 돌린다. `6`은 명령이 실행됐고 실패했다는 뜻이다. **같은 명령을 그대로 다시 돌리지 않는다.**

### 쓰지 않는 것

`simulate_key`, `set_timescale`, `runtime_status`, `log`은 Runtime 서버 명령이라 개발용 Player 빌드가 있어야 한다. 이번 범위에서는 쓰지 않는다. 입력 확인은 자동 재생과 테스트로 한다.

### `Assets/GPGR/Charting/Judgement.cs`

```csharp
using System;
using UnityEngine;

namespace GPGR.Charting
{
    public enum Judgement { Perfect, Good, Bad, Miss }

    [Serializable]
    public struct JudgementWindows
    {
        [Tooltip("ms")] public double perfectMs;
        [Tooltip("ms")] public double goodMs;
        [Tooltip("ms")] public double badMs;
        [Tooltip("%p")] public float perfectPenalty;
        [Tooltip("%p")] public float goodPenalty;
        [Tooltip("%p")] public float badPenalty;
        [Tooltip("%p")] public float missPenalty;

        public static JudgementWindows Default => new JudgementWindows
        {
            perfectMs = 50.0, goodMs = 100.0, badMs = 160.0,
            perfectPenalty = 0f, goodPenalty = 2f, badPenalty = 5f, missPenalty = 10f,
        };

        /// 윈도우가 서로 겹치므로 위에서부터 먼저 맞는 줄을 쓴다.
        public Judgement Classify(double absErrorMs)
        {
            if (absErrorMs <= perfectMs) return Judgement.Perfect;
            if (absErrorMs <= goodMs) return Judgement.Good;
            if (absErrorMs <= badMs) return Judgement.Bad;
            return Judgement.Miss;
        }

        public float PenaltyOf(Judgement j)
        {
            switch (j)
            {
                case Judgement.Perfect: return perfectPenalty;
                case Judgement.Good: return goodPenalty;
                case Judgement.Bad: return badPenalty;
                default: return missPenalty;
            }
        }
    }
}
```

### `Assets/GPGR/Charting/SongChart.cs`

```csharp
using System.Collections.Generic;
using UnityEngine;

namespace GPGR.Charting
{
    public enum PlaybackMode { AutoPlay, Human }

    [CreateAssetMenu(fileName = "SongChart", menuName = "GPGR/Song Chart")]
    public sealed class SongChart : ScriptableObject
    {
        public float bpm = 120f;
        [Tooltip("클락은 오디오 시각에 이 값을 더한다.")] public double offsetSeconds;

        [Tooltip("프리셋이 첫 경로 키의 시각을 만들 때 쓴다.")] public double defaultApproachBeats = 2.0;
        public float defaultSpawnAngleDeg = 180f;

        [Tooltip("비어 있어도 된다. 그때는 BPM만으로 돈다.")] public AudioClip clip;

        public JudgementWindows judgement = JudgementWindows.Default;

        public PlaybackMode playback = PlaybackMode.AutoPlay;
        [Tooltip("자동 재생에서 Good이 나올 비율. 나머지는 Perfect.")]
```

```csharp
    {
```

```csharp
        public readonly double OriginBeat;         // 절대 박
        public readonly double EarliestSpawnBeat;  // 절대 박
        public readonly double ClearedBeat;        // 절대 박
        public PhaseWindow(int phaseIndex, double originBeat, double earliestSpawnBeat, double clearedBeat);
    }

    public static class ChartLayout
    {
        /// 페이즈를 곡 박자에 펼친다. 판정 결과와 무관한 순수 함수다.
        public static List<PhaseWindow> Build(SongChart chart);

        public static List<string> Validate(SongChart chart);
```

`Build` 알고리즘은 `Docs/Unity_구조.md` §2를 그대로 옮긴다.

```text
cursor = 0
페이즈마다:
    earliestLocal = rows가 있으면 min(SpawnBeat(row)), 없으면 0
    clearedLocal  = max( rows가 있으면 max(ClearBeat(row, chart)) : 0 , holdBeats )
    origin  = cursor - earliestLocal
    cleared = origin + clearedLocal
    → PhaseWindow(i, origin, cursor, cleared)
    cursor  = cleared
```

판정 결과로 노트가 일찍 사라져도 이 값은 다시 계산하지 않는다.

## 5. `GPGR.Runtime` 공개 면 (B가 만들고 C가 읽는다)

B는 내부 구현을 자유롭게 하되, 아래 **공개 멤버 이름과 시그니처는 고정**이다. C가 이것만 보고 뷰를 짠다.

```csharp
namespace GPGR.Runtime
{
    // 노트 한 개의 상태. 패턴 객체는 이걸 저장하지 않는다.
    public sealed class NoteInstance
    {
        public NoteRow Row { get; }
        public int PhaseIndex { get; }
        public double OriginBeat { get; }     // 절대 박
        public int HitCount { get; }
        public Judgement LastJudgement { get; }
        public bool HasJudged { get; }
        public float AngleDeg { get; }        // 현재 각도. 매 프레임 경로 키에서 다시 구한다.
        public bool Cleared { get; }
```

## 6. 마일스톤

M0(공용 타입과 asmdef)은 끝나 있다. **셋이 동시에 M1부터 시작한다.**

| | A · 데이터와 에디터 | B · 런타임 코어 | C · 뷰와 연출 |
| --- | --- | --- | --- |
| M1 | `GPGR/Chart Editor` 창이 페이즈·행을 편집 | 클락 + 레이아웃 소비 + 스폰 + 판정이 로그로 확인 | 원판·히트 라인·노트 아이콘이 플레이스홀더로 돈다 |
| M2 | `GPGR/Create Demo Chart Asset` + 검증 + 테스트 | 자동 재생 + 정확도 + 입력 라우팅 | 트레일·꼬리·배경·오븐·HUD |
| M3 | 셋이 합류. 데모 에셋으로 트레일러 씬이 자동 재생으로 끝까지 한 번 돈다 | | |

M3 합류 전까지 C는 손으로 만든 임시 차트로 확인한다. A가 데모 에셋을 올리면 그걸로 바꾼다.

## 7. 잠정 숫자

기획 문서에서 "아직 비어 있다"고 한 값들이다. **잠정**이므로 기본값으로만 쓰고, 나중에 에셋에서 바꿀 수 있게 둔다. 코드에 상수로 박지 않는다.

| 값 | 잠정 | 쓰는 곳 |
| --- | --- | --- |
| BPM / 오프셋 | 120 / 0초 | A |
| 반죽 꼬리 길이 | 2박 | A |
| 오븐 꼬리 길이 | 4박 | A |
| 페퍼로니 접근 박 | 1박 | A |
| 치즈 되돌아가는 각도 | 270° → 210° (−60°) | A |
| 치즈 두 번째 히트까지 | 2박 (튕김 정점 1박, 복귀 1박) | A |
| 완성 페이즈 `holdBeats` | 8박 | A |
| Bad / Miss 감점 | −5%p / −10%p | A |
| 자동 재생 Good 비율 / 시드 | 0.25 / 12345 | B |
| 원판 중심 / 반지름 | (0, 0) / 3.0 유닛 | C |
| 트레일 길이 / 두께 / 페이드 | 0.5박 / 반지름의 0.06 / 0.2초 | C |
| 배경 전환 시간 | 0.3초 | C |
| 피자 오븐 인·아웃 | 스케일 1.0 → 0.35, 0.6초 | C |

### 데모 채보 잠정 (A가 만든다)

BPM 120에서 1박 = 0.5초. Bad 창 160ms ≈ 0.32박.

| # | 페이즈 | 배경 / 피자 | 행 | 히트 박(페이즈 기준) | 경로 키 | 꼬리 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 반죽 | 밝음 / 없음 | Long ×1 | 2.0 | (0,180) (2,270) | 2박 |
| 2 | 토마토 소스 | 밝음 / 없음 | Single ×2 | 2.0 / 4.0 | (0,180)(2,270) / (2,180)(4,270) | — |
| 3 | 치즈 뿌리기 | 밝음 / 없음 | Single ×1 | 2.0, 4.0 | (0,180) (2,270) (3,210) (4,270) | — |
| 4 | 페퍼로니 | 밝음 / 없음 | Single ×4 | 1.0 / 2.0 / 3.0 / 4.0 | 각 (히트−1,180) (히트,270) | — |

## 8. 막히면

- 계약을 바꿔야 할 것 같으면 **코드를 고치지 말고** 사람에게 묻는다. 셋이 같은 타입을 쓰므로 한쪽이 몰래 바꾸면 나머지 둘이 깨진다.
- 기획 문서와 이 계약이 어긋나면 기획 문서가 맞다. 계약의 버그로 보고한다.
- 남의 폴더에 파일이 필요하면 직접 만들지 말고 요청 사항으로 남긴다.
