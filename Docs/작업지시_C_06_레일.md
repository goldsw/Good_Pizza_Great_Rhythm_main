# 작업지시 C-06 — 레일을 고리로

담당: C (뷰와 연출)

구현이 사각형을 자르고 있으면 `Docs/작업지시_C_07_레일수정.md`를 따른다.

A와 B는 하지 않는다. 레일은 노트가 지나가는 고정 궤도이고, `Docs/Unity_구조.md`의 보이는 쪽이다. 판정과 반지름 계산은 그대로다.

지금 `OrbitTrackView`는 원 위에 검은 파티클을 찍는다. 점이 겹치면 굵어지고, 수명이 끝나면 오른쪽 호만 남는다. 그 파티클 레일을 끈다. 스폰 이펙트와 타격 이펙트 파티클은 유지한다.

---

## 1. 모양

검은 원판에서 가운데를 빼 고리만 남긴다.

1. 검은 원 스프라이트를 궤도 크기로 둔다.
2. 그보다 작은 원형 `SpriteMask`로 가운데를 지운다. 마스크 바깥만 보이게 한다.
3. 남는 띠가 레일이다.

3D 원통은 만들지 않는다. 카메라가 2D다. 구멍의 의미만 가져오고, 구현은 스프라이트와 마스크다.

두께는 바깥 반지름과 구멍 반지름의 차이다. 인스펙터에 `두께`를 둔다. 잠정값은 궤도 반지름의 0.08배다. 코드에 픽셀 두께를 박지 않는다.

색은 검다. 나무 원판 스프라이트(`Ring`)를 레일로 쓰지 않는다. 그 그림은 도마다.

---

## 2. 붙이는 자리

중심과 반지름은 `NoteWheel`에서 읽는다. `Center`는 `Wheel`의 위치이고, `radius`는 씬 값이다. 레일만 따로 옮기거나 키우지 않는다.

| 규칙 | 값 |
|---|---|
| 부모 | `Wheel` |
| 위치 | 원판 중심 |
| 바깥 반지름 | `NoteWheel.radius` |
| 정렬 | 피자(5)보다 앞, 노트 아이콘(20)보다 뒤. 잠정 7 |
| 회전 | 없음. 노트가 고리 위를 돈다 |

히트 마커는 고리 위 270°에 둔다. `WheelView`가 이미 그 각도로 마커를 놓는다. 마커를 고리 자식으로 넣어 같이 잘리게 하지 않는다.

`TrailView`는 노트 잔상이다. 고리와 합치지 않는다.

---

## 3. 씬

`OrbitTrack`의 파티클 재생을 끈다. 고리는 그 오브젝트에 붙이거나, 뷰 코드가 매 프레임 반지름에 맞춰 크기를 다시 잡는다. 플레이 중에 `WheelView`가 링 크기를 반지름으로 덮어쓰듯, 고리도 한 번 맞추고 끝내지 않는다. `radius`가 바뀌면 고리도 바뀐다.

마스크의 범위는 고리 스프라이트만 자른다. 배경, 피자, 노트, HUD가 가운데 구멍 때문에 사라지면 마스크 범위가 잘못된 것이다.

---

## 4. 확인

`editor_play` 후 `capture_game_view --source screen`.

| 볼 것 | 맞는 모습 |
|---|---|
| 고리 | 나무판 바깥의 검은 띠. 두께가 일정하다 |
| 가운데 | 피자와 도마가 보인다. 검게 덮이지 않는다 |
| 노트 | 고리 위를 돌고, 고리는 따라 돌지 않는다 |
| 히트 마커 | 고리 하단(270°)에 있다 |
| 배경·HUD | 마스크에 잘리지 않는다 |
