## 1. 채보를 갈아탄다

### 무엇이 잘못돼 있나

`Trailer.unity`의 `TrailerBootstrap` 컴포넌트에 있는 `chart` 필드가 아직 임시 채보를 가리킨다. 씬 파일을 뒤져 확인했다.

| 에셋 | guid | 씬이 참조하는가 |
|---|---|---|
| `Assets/GPGR/Charts/DemoChart.asset` | `89bc02f166d49e54d90d151961c5d925` | 아니다 |
| `Assets/GPGR/Scenes/TempTrailerChart.asset` | `4c8e1a32b7d64f0a9c2e5b18d6a30132` | **그렇다** |

바꿔야 하는 곳은 `TrailerBootstrap.cs`의 이 필드 하나다.

```14:15:Assets/GPGR/View/TrailerBootstrap.cs
        [Tooltip("A의 DemoChart가 오기 전에는 손으로 만든 임시 차트를 넣는다.")]
        [SerializeField] SongChart chart;
```

### 어떻게 하나

`TrailerEditor.cs`에 메뉴를 하나 더 붙여서 하는 것을 권한다. 이미 `GPGR/View/Add Runtime Components`가 있으니 같은 자리에 두면 된다. 손으로 인스펙터를 끌지 말고 코드로 해라. 그래야 다시 돌릴 수 있고, 나중에 채보가 또 바뀌어도 메뉴만 실행하면 된다.

`AssetDatabase.LoadAssetAtPath<SongChart>`로 에셋을 집고, 씬에서 `TrailerBootstrap`을 찾아 `chart`에 꽂고, **`EditorSceneManager.MarkSceneDirty` 뒤에 씬을 저장**한다. 저장을 빠뜨리면 아무 일도 일어나지 않는다.

`chart`는 `private [SerializeField]`라서 밖에서 직접 대입할 수 없다. `SerializedObject` / `FindProperty("chart")` / `objectReferenceValue` / `ApplyModifiedProperties`를 쓰거나, 에디터 전용 세터를 만든다. 전자가 깔끔하다.

### 위험도

낮다. 두 채보를 비교해 봤다.

| | DemoChart | TempTrailerChart |
|---|---|---|
| 크기 | 4429 바이트 | 4375 바이트 |
| bpm | 120 | 120 |
| perfect/good/bad (ms) | 50 / 100 / 160 | 50 / 100 / 160 |
| good/bad 감점 | 2 / 5 | 2 / 5 |
| playback | 0 = AutoPlay | 0 = AutoPlay |
| autoGoodRatio | 0.25 | 0.25 |

구조가 거의 같으니 꽂으면 그냥 돌 가능성이 높다. `playback`이 둘 다 `AutoPlay`라 자동 연주도 그대로 켜진다.

### TempTrailerChart는 지우지 마라

교체가 확실히 동작하는 것을 확인할 때까지 남겨 둔다. 되돌릴 자리가 필요하다. 검증이 끝나면 지울지 말지는 보고에 적고 판단을 받는다.

## 2. 돌려 보고 확인한다

`editor_play`는 너만 쓸 수 있다. 다른 에이전트는 이걸 켜지 않는다.

키는 `TrailerBootstrap`에 이렇게 붙어 있다.

- `R` 처음부터 다시
- `H` HUD 켜고 끄기
- `F` 단색 배경 켜고 끄기

### 볼 것

| 확인할 것 | 무엇이 맞는 모습인가 |
|---|---|
| 페이즈 진행 | 반죽 → 소스 → 치즈 → 페퍼로니 → 화덕 → 완성 순서로 끊김 없이 넘어간다 |
| 페이즈 겹침 | 앞 페이즈 노트가 남아 있는데 다음 페이즈 노트가 나오지 않는다 |
| 노트 이동 | 스폰 각에서 나와 히트 각으로 돈다. 히트 순간에 마커와 겹친다 |
| 자동 연주 | **Perfect와 Good만 나온다.** Bad나 Miss가 하나라도 뜨면 버그다 |
| 정확도 | 100에서 시작해 조금만 깎인다. `autoGoodRatio`가 0.25니 Good이 4번에 1번쯤 섞인다 |
| 롱노트 꼬리 | 머리에서만 판정하고 꼬리가 길이대로 그려진다 |
| 테마 | 화덕 페이즈에서 배경이 어두워진다. 반죽~페퍼로니는 같은 밝은 배경이고 노트 아이콘·색으로만 구분된다 |
| 피자 | 페이즈가 넘어갈 때마다 재료가 쌓인다 |
| HUD | 페이즈 이름이 지금 페이즈와 맞다 |
| 노트 없는 페이즈 | "완성"이 `holdBeats` 동안 머문다. 순간에 지나가면 버그다 |

### 주의할 것 하나

`Start()`에서 `Screen.SetResolution(1920, 1080, Windowed)`을 부른다.

```34:35:Assets/GPGR/View/TrailerBootstrap.cs
            Screen.SetResolution(captureWidth, captureHeight, FullScreenMode.Windowed);
            BeginChart();
```

에디터 플레이 모드에서 `Screen.SetResolution`은 무시되거나 이상하게 먹는다. Game 뷰의 종횡비가 1920x1080으로 안 잡히면 이것 때문이다. Game 뷰 해상도를 직접 1920x1080 고정으로 맞춰 놓고 확인해라.

## 3. 화면을 남긴다

```
unity command capture_game_view --source screen
```

`--source screen`을 꼭 붙인다. 그냥 찍으면 오버레이로 그린 UI가 안 담겨서 HUD가 빠진다.

페이즈마다 한 장씩 남겨서 여섯 페이즈가 서로 구분되는지 눈으로 확인한다. 특히 반죽·소스·치즈·페퍼로니 네 장은 배경이 같으니, **노트 아이콘과 색만으로 구분이 되는지**가 핵심이다. 구분이 안 되면 그건 A가 채보의 `icon`·`color`를 덜 채운 것이므로 고치지 말고 보고해라.
